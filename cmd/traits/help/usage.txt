traits - check changes against your project's traits with a decision model

Usage:
  traits check [options] path...
  traits check [options] --diff                  read a unified diff from stdin
  traits check [options] --assume-filename NAME  read one file from stdin
  traits explain [--rules dir] [trait...]        print the questions sent to the model
  traits hook claude|codex [options]             agent PostToolUse hook (payload on stdin)
  traits hook install claude|codex [--apply] [--scope project|user]
  traits recheck [options]                       Stop hook: record fixed/kept outcomes
  traits findings [--summary] [--format text|json]
  traits skill install [--agent claude|codex|opencode] [--apply]
  traits version

A trait is a Markdown file in .agents/traits/<name>.md:

  ---
  name: colocate-domain-errors
  subject: Small domain-specific error types.
  requirement: Define them beside the operations that produce them.
  purpose: Keep error definitions close to their meaning.
  appliesTo: ["*.ts"]          # optional path globs
  when: ["extends Error"]      # optional regexes over changed lines
  fix: Move the type into the module that throws it.   # optional
  scope: hunk                  # hunk (default) or file
  status: active               # active (default) or candidate
  ---
  Optional context: examples, diffs, references.

Check options:
  --provider name     openai (default), openrouter, systemone, opencode, cloudflare
                      ($TRAITS_PROVIDER)
  --model name        model ($TRAITS_MODEL; default: the provider's)
  --rules dir         traits directory ($TRAITS_DIR; default .agents/traits at the repo root)
  --format f          json (default), text, summary, sarif
  --fail-on tier      exit 1 on a finding of this tier: fix (default), review, never
  --jobs n            files checked concurrently (default 8)
  --timeout d         per-request timeout including retries (default 30s)
  --retries n         retries on 429 and 5xx (default 2; use 0 in hooks)
  --repo dir          repository root for reading post-change files
  --no-cache          bypass the answer cache in .agents/traits/.cache

Output:
  Results go to stdout in the chosen format; the one-line summary and file
  errors go to stderr. Findings have a tier: "fix" (violation probability at
  or above the trait's fix threshold, default 0.8) or "review" (at or above
  0.5, or the model could not decide).

Hooks:
  `traits hook claude` (Write|Edit|MultiEdit) and `traits hook codex`
  (apply_patch) check the edit just made and report up to --top (default 5)
  findings as PostToolUse additionalContext JSON. `traits recheck` (Stop)
  re-checks files with open findings from the session and logs whether they
  were fixed or kept. Both fail open: on any error, missing traits or
  credentials, or after $TRAITS_HOOK_TIMEOUT (default 8s), they print
  nothing and exit 0. Hook options: --provider, --model, --rules, --timeout,
  --top. Set TRAITS_HOOK_DEBUG=1 to see why a hook stayed silent (stderr).

  `traits hook install` merges the hooks into .claude/settings.json or
  .codex/hooks.json (--scope user: under your home directory). It is a dry
  run unless --apply; existing files are backed up to <file>.bak-<time>.

Findings log:
  check, hook and recheck append to .agents/traits/.cache/findings.jsonl.
  `traits findings --summary` shows per trait how often it was flagged,
  fixed and kept; a high keep rate suggests a trait worth refining.

Exit status:
  0    checks ran and nothing reached --fail-on
  1    a finding reached --fail-on, or a file could not be fully checked
  2    the command line, traits directory, or provider configuration is unusable
  3    the provider failed (unreachable, refused, malformed answer)
  130  interrupted
  hook and recheck always exit 0.

Examples:
  git diff HEAD | traits check --diff --format summary
  git diff origin/main...HEAD | traits check --diff --format sarif > traits.sarif
  traits check --provider systemone --model nimble src/
